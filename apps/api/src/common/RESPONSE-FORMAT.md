# Standard Response Format

This document defines the standard response format for all API endpoints.

## Success Response

All successful responses should follow this structure:

### Basic Response (200 OK)

```json
{
  "data": {
    "id": "123e4567-e89b-12d3-a456-426614174000",
    "email": "user@example.com",
    "name": "John Doe"
  },
  "message": "User retrieved successfully"
}
```

### Response with Pagination

```json
{
  "data": [
    { "id": "1", "name": "Item 1" },
    { "id": "2", "name": "Item 2" }
  ],
  "message": "Items retrieved successfully",
  "meta": {
    "total_count": 100,
    "limit": 20,
    "offset": 0,
    "total_pages": 5
  }
}
```

### Response Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| data | any | yes | The actual response data |
| message | string | no | Human-readable message |
| meta | object | no | Pagination or other metadata |

## Error Response

All error responses follow this structure:

```json
{
  "statusCode": 400,
  "message": "Validation failed",
  "errors": [
    {
      "field": "email",
      "message": ["Email is required", "Email must be valid"]
    }
  ],
  "timestamp": "2024-01-01T12:00:00.000Z",
  "path": "/api/auth/login",
  "correlationId": "123e4567-e89b-12d3-a456-426614174000"
}
```

### Error Response Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| statusCode | number | yes | HTTP status code |
| message | string | yes | Human-readable error message |
| errors | array | no | Field-level validation errors |
| timestamp | string | yes | ISO 8601 timestamp |
| path | string | yes | Request path |
| correlationId | string | yes | Unique request identifier |

## Pagination

For list endpoints, responses should include pagination metadata:

```json
{
  "data": [
    { "id": "1", "name": "Item 1" },
    { "id": "2", "name": "Item 2" },
    { "id": "3", "name": "Item 3" }
  ],
  "meta": {
    "total_count": 150,
    "limit": 3,
    "offset": 0,
    "total_pages": 50
  }
}
```

### Pagination Query Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| limit | number | 20 | Items per page (max 100) |
| offset | number | 0 | Items to skip from the beginning |

### Pagination Metadata

| Field | Type | Description |
|-------|------|-------------|
| total_count | number | Total items in the collection |
| limit | number | Items returned in this page |
| offset | number | Items skipped from the beginning |
| total_pages | number | Total number of pages |

## Timestamps

All timestamps should be in ISO 8601 format with UTC timezone:

```
2024-01-01T12:00:00.000Z
```

## HTTP Status Codes

| Code | Usage |
|------|-------|
| 200 | Successful GET, PUT, PATCH |
| 201 | Successful POST (resource created) |
| 204 | Successful DELETE or empty response |
| 400 | Validation error or bad request |
| 401 | Missing or invalid authentication |
| 403 | Insufficient permissions |
| 404 | Resource not found |
| 409 | Conflict (e.g., duplicate entry) |
| 422 | Unprocessable entity (semantic error) |
| 429 | Rate limit exceeded |
| 500 | Internal server error |
| 503 | Service unavailable |

## Correlation ID

Every request/response includes a unique correlation ID for request tracking:

### In Request
```
X-Correlation-ID: 123e4567-e89b-12d3-a456-426614174000
```

### In Response
```
X-Correlation-ID: 123e4567-e89b-12d3-a456-426614174000
```

If not provided in the request, one is generated by the server.

## Rate Limiting Headers

All responses include rate limit information:

```
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 99
X-RateLimit-Reset: 2024-01-01T12:01:00.000Z
```

## Examples

### Example 1: Create User

**Request**
```
POST /api/users
Content-Type: application/json

{
  "email": "john@example.com",
  "name": "John Doe"
}
```

**Response (201 Created)**
```json
{
  "data": {
    "id": "123e4567-e89b-12d3-a456-426614174000",
    "email": "john@example.com",
    "name": "John Doe",
    "createdAt": "2024-01-01T12:00:00.000Z"
  },
  "message": "User created successfully"
}
```

### Example 2: List Users with Pagination

**Request**
```
GET /api/users?limit=10&offset=0
```

**Response (200 OK)**
```json
{
  "data": [
    {
      "id": "123e4567-e89b-12d3-a456-426614174000",
      "email": "john@example.com",
      "name": "John Doe"
    },
    {
      "id": "123e4567-e89b-12d3-a456-426614174001",
      "email": "jane@example.com",
      "name": "Jane Doe"
    }
  ],
  "meta": {
    "total_count": 50,
    "limit": 10,
    "offset": 0,
    "total_pages": 5
  }
}
```

### Example 3: Validation Error

**Request**
```
POST /api/users
Content-Type: application/json

{
  "email": "invalid-email",
  "name": ""
}
```

**Response (400 Bad Request)**
```json
{
  "statusCode": 400,
  "message": "Validation failed",
  "errors": [
    {
      "field": "email",
      "message": ["Email must be valid"]
    },
    {
      "field": "name",
      "message": ["Name is required"]
    }
  ],
  "timestamp": "2024-01-01T12:00:00.000Z",
  "path": "/api/users",
  "correlationId": "123e4567-e89b-12d3-a456-426614174000"
}
```

### Example 4: Authentication Error

**Request**
```
GET /api/protected
```

**Response (401 Unauthorized)**
```json
{
  "statusCode": 401,
  "message": "No authentication token provided",
  "timestamp": "2024-01-01T12:00:00.000Z",
  "path": "/api/protected",
  "correlationId": "123e4567-e89b-12d3-a456-426614174000"
}
```

## Implementation in Nestjs

### Using SuccessResponseDto

```typescript
import { SuccessResponseDto } from '../common/dtos';

@Get(':id')
async getUser(@Param('id') id: string) {
  const user = await this.usersService.findOne(id);
  return new SuccessResponseDto(user, 'User retrieved successfully');
}
```

### Using SuccessResponseDto with Pagination

```typescript
import { SuccessResponseDto, PaginationMeta } from '../common/dtos';

@Get()
async listUsers(
  @Query('limit') limit: number = 20,
  @Query('offset') offset: number = 0,
) {
  const { items, total } = await this.usersService.list(limit, offset);
  const meta = new PaginationMeta(total, limit, offset);
  return new SuccessResponseDto(
    items,
    'Users retrieved successfully',
    meta,
  );
}
```
